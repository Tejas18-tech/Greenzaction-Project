# Greenzaction delivery checklist

- [x] **Project foundation and visual system** — The project uses React/Vite, Flask, MongoDB-ready persistence, custom responsive CSS without Tailwind, Lucide-compatible icons, Inter for interface text and JetBrains Mono for technical data, with forest green/emerald and clean white surfaces.
- [x] **Authentication and permissions** — Registration and login use secure password hashing and JWT sessions; user profile management works; user and admin access are separate; users can access only their own financial records and admin endpoints require admin authorization.
- [x] **Transaction management** — Users can create, edit, delete, search, filter, paginate and import CSV transactions; simulated UPI, card and wallet payment methods are supported; transactions include merchant, amount, date, category, payment method and description; simulated payments are not represented as real bank transfers.
- [x] **Carbon calculation workflow** — Every valid transaction identifies a category and emission factor, estimates carbon with Activity Data × Emission Factor, generates a rating, stores source/method/confidence and updates derived dashboard data; unsupported product detail is clearly treated as a category estimate rather than amount-as-physical-measurement.
- [x] **Scores, rewards and achievements** — Green Score is 0–100, ratings are A–E, eligible purchases award points once, reward history and total points are tracked, and badges/achievements are represented.
- [x] **Dashboard and analytics** — Database-backed metrics show spending, kg CO₂e, Green Score, rating, points, eco-friendly percentage, recent transactions, monthly footprint, category emissions, spending analytics, date filters and interactive charts.
- [x] **Recommendations and GreenBot** — Recommendations use actual transaction history and Gemini/AI when configured with rule fallback; GreenBot answers footprint, highest category, monthly spend, score, reduction advice and points from authenticated records without invented statistics.
- [x] **Goals, profile and admin** — Sustainability goals and profile pages are functional; admin dashboard covers users, transaction statistics, estimated emissions, activity, emission factors, rewards and categories.
- [x] **Documentation and verification** — `.env.example`, realistic demo seed data, complete install/run instructions, route manifest and build/smoke checks are included; major auth, transaction, calculation, rewards, analytics, AI, privacy, admin and CSV flows are exercised.
